# FINAL 验收账号与固定素材

本目录中的内容均为虚构验收材料。最终验收应在现有数据库中新建带 `FINAL` 标识的数据，不复用、不删除、不修改开发阶段的调试记录。

## 测试账号

| 账号 | 密码 | 建议用途 |
|---|---|---|
| `demo_a` | `Demo-A-2026!` | 创建 FINAL 素材并执行完整流程 |
| `demo_b` | `Demo-B-2026!` | 验证账号隔离和越权访问返回 404 |

这些是本地公开验收账号，不是生产凭据。

## 组合 A：较匹配场景

- 简历文件：[resume-match.md](resume-match.md)
- 简历标题：`FINAL-A-较匹配-后端开发简历`
- 岗位文件：[job-match.md](job-match.md)
- 岗位名称：`FINAL-A-后端开发工程师`

预期观察点：岗位与简历在 Python、FastAPI、REST API、PostgreSQL、Docker / Docker Compose 等方面存在较多可核对原文；对于仅有部分证据支持的要求，应根据实际证据保守判断为已体现或需要补充确认。具体判断、证据、建议和最终状态必须以真实模型调用及后端校验结果为准，不能预先写成实际结果。

## 组合 B：信息缺口与事实边界场景

- 简历文件：[resume-gap.md](resume-gap.md)
- 简历标题：`FINAL-B-信息缺口-初级后端简历`
- 岗位文件：[job-gap.md](job-gap.md)
- 岗位名称：`FINAL-B-云原生后端工程师`

固定边界：

- 项目经历没有量化成果。
- 简历使用“参与”“协助”等有限职责，没有声称独立负责或主导。
- 简历只写“了解 Linux”，岗位要求“熟练使用 Linux”。
- 岗位要求 PostgreSQL、Redis、Docker、Kubernetes，简历均未提及。
- 岗位要求 FastAPI，简历只写 Flask。

预期观察点：信息缺口应表现为未体现或需要补充确认；系统不得自动加入缺失技能、独立负责经历或量化成果。具体模型结果仍须在最终验收时实际记录。

## 使用规则

1. 仅复制各素材正文到应用，不把本文件中的“预期观察点”复制进简历或岗位描述。
2. 新建的 Resume、Job 和 Analysis 名称均保留 `FINAL-A` 或 `FINAL-B` 标识。
3. 不删除或修改 demo_a、demo_b 中已有调试数据。
4. 不把验收预期写成实际结果；实际 ID、状态、证据、版本和导出文件统一填写到 `docs/最终验收报告.md`。
5. Markdown 示例导出必须由应用实际下载后另行保存，不能根据这些素材手工重建。
