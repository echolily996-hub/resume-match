# 要求、证据与修改建议的对应关系

一条主要岗位要求填写一行。job_requirement_quote 引用本次岗位快照原文，resume_evidence_quote 引用本次简历快照原文，没有对应内容就留空，不能让模型伪造引文。

| match_status | 如何理解 | 修改稿处理 |
|---|---|---|
| 已体现 | 能用简历原文支持该要求 | 可优化表达，但不扩大事实范围 |
| 未体现 | 当前简历找不到该要求的证据 | 提示缺口，不推断“用户不会”，不自动补入技能 |
| 需要补充确认 | 有相关线索，但具体责任、范围或结果不明确 | 将补充问题单列，未确认前不作为事实写入 |

涉及改写时填原段落、建议段落和理由；只有补充问题时建议文本可空。decision 填未处理 / 采纳 / 忽略。saved_revision 关联保存后的修改稿版本，evidence_ref 指向页面或测试证据。

## 自备材料应包含的边界

- 一份简历有真实明确的项目描述，但没有量化结果：系统不能自行补出“提升 30%”等数字。
- 一个岗位要求简历没写的技能：标为未体现或待确认，不直接添加到技能栏。
- 有团队项目但未说个人负责范围：询问职责，不能直接改为“独立负责整个系统”。
- 一组资料明显较匹配，另一组有缺口：输出应随输入变化，不能是同一固定报告。

## 修改及版本核对

原稿是创建时输入；分析快照是每次分析时的简历与岗位；修改稿是用户采纳、编辑并保存的正文，三者用途不同。采纳影响当前修改稿，不改原始输入；忽略不改变正文；重复采纳不会重复插入。

手动编辑和采纳后显式保存，随后导出已保存内容。页面仍有未保存改动时，应清楚说明导出的是保存稿，或先引导保存，不能悄悄导出另一个版本。新建一次分析必须有独立结果和输入快照，不覆盖旧的已保存修改稿。

Markdown 导出可有合理的标题、列表格式，但文本内容必须对应保存稿；模型判断、解释、被忽略建议和未确认问题均不属于简历正文。不要以“模型会幻觉”为理由把事实检查交给最终导出阶段。
